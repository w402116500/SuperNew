💡 为什么构建 SuperMew：解决传统 RAG 的核心致命伤
传统 RAG 普遍存在“固定切分打碎表格与层级上下文”、“向量召回在专有名词与编号检索上命中率低”、“单 Agent 链式调用无法应对复杂多跳对比问题”以及“模型幻觉与不可信引用”四大难题。SuperMew 通过自建 L1/L2/L3 三级父子分块索引、BGE-M3 密集向量 + Milvus 2.5 原生 BM25 稀疏检索 RRF 双路融合、LangGraph Send 扇出并行多 Agent 规划 以及 全链路可复现 300 题评测闭环，打造真正面向生产的受控问答基座。

⚖️ SuperMew 核心技术决策与设计权衡矩阵 Production Architectural Trade-offs
核心维度 传统朴素 RAG 方案 (Baseline) SuperMew 企业级落地决策 工程权衡与收益 (Trade-offs & Benefits)
文档切分与结构保护 固定字符长度切分（512/50），无视文档结构，表格和标题被粗暴截断。 Markdown AST 树 + L1/L2/L3 三级父子分块（章节 2400 / 语义块 1600 / 检索叶子 800）。 消除表格截断与语义碎片化。L3 负责高灵敏检索，命中后自动向上提升至 L2 完备上下文输入 LLM。
多路召回与融合算法 仅稠密向量检索，在型号、订单号、金额等专业词汇上极其容易漏召回。 BGE-M3 (1024 维) + Milvus 2.5 原生 BM25 稀疏检索 + RRF ($k=60$) 融合。 避免传统单向量的“语义泛化导致专有名词失真”。Milvus 服务端计算 BM25，免去外挂 Elasticsearch 的运维成本。
精排与容灾降级 无 Reranker 或仅做简单点积，若外接重排服务挂掉则全链路 500 报错。 Qwen Reranker 交叉注意力打分 + 0.45 阈值过滤 + 90s 超时自动熔断降级。 有效剔除无关候选项。若 Reranker 推理超时或宕机，自动平滑回退为原始 RRF 排序，确保 100% 可用性。
复杂问题编排引擎 单次 Prompt 强行让大模型完成多跳推理，容易出现注意力漂移和遗漏。 LangGraph 状态图 + Send 算子并发扇出 + FastModel 复杂度路由。 将复杂对比问题正交拆分为 2~4 个独立子检索任务，并发执行，结果原子归约，准确率净增 7.33%。
回答可信度与防幻觉 完全依赖大模型自觉，无引用或捏造虚假引用，回答不可审计。 EvidenceGrade 结构化评分门禁 + 强制真实 `[1]`, `[2]` 溯源锚点绑定。 严格验证检索证据与提问的槽位覆盖率；无法回答时触发拒答或澄清，杜绝企业级场景下的业务幻觉。

🧪 典型生产混沌工程演练场景与系统自愈表现 (Chaos Scenarios)
场景 A: Reranker GPU 突发显存 OOM
精排跨编码器在处理突发超长 query 时显存耗尽。系统在 _call_rerank_service 捕获 HTTP 500/Timeout 异常，立即触发熔断，记录警告日志，无缝回退至 RRF 融合排序结果，用户在 350ms 内正常获取回答，业务零中断。
场景 B: Redis 缓存集群瞬断
Redis 哨兵进行主从切换（约 2 秒断连）。FastAPI 读取 L1/L2 缓存失败后，自动穿透至 PostgreSQL 查询，布隆过滤器拦截不存在 Key，写操作异步重试，PG 连接池保持在安全阈值，业务响应时间仅轻微抖动 +12ms。
场景 C: 客户端意外断开连接 (Tab 关闭)
用户在模型生成途中关闭浏览器或点击“停止生成”。FastAPI request.is_disconnected() 实时侦测，立即抛出 CancelledError，级联终止下游 LangGraph 异步子图与 LLM 握手，瞬间释放昂贵的推理显存与 Token 预算。

🛡️ 跨层防污染核心准则
  • 检索层绝不直接喂给 LLM：Milvus 只存储 L3 叶子块，负责算分与召回；LLM 输入的必须是由 ParentChunkStore 提升后的 L2/L1 语义块，防止把被切断的残破表格直接送入模型。
  • 单请求绝不碰全局变量：所有 SSE 流式事件、中间思考痕迹与取消信号全部严格通过 ChatRequestContext 闭包传递，确保高并发多租户场景下 0 串流、0 数据交叉。
  • 入库绝不破坏线上旧索引：新建索引与解析文件全部在独立 staging/ 暂存区闭环，只有通过完备性指标测试后才触发原子重命名与指针倒换。

隔离维度 技术落地机制与指令规范 安全收益与防御边界
Milvus 向量检索隔离 在每一次 AnnSearchRequest 中强制注入 expr="tenant_id == '...' and kb_id in [...]"，禁止执行无租户约束的裸检索。 保证即使稠密向量相似度极高，跨租户未授权文档的物理行也绝不可能进入候选召回池。
PostgreSQL 行级安全 (RLS) 数据库连接池借出连接后，立即通过事务设置 SET LOCAL app.current_tenant_id = '...'，由 PG 内核执行行级过滤。 杜绝研发人员手写 SQL 忘记拼接 WHERE tenant_id = ... 导致的大规模越权数据泄露漏洞。
Redis 缓存空间隔离 所有 Redis 键均带有统一租户前缀：chunk:{tenant_id}:{doc_id}:{level}:{idx} 与 session:{tenant_id}:{session_id}。 防止多租户场景下相同 doc_id 产生的缓存覆盖冲突，支持按租户执行批量缓存清空与容量配额限制。
运行期内存与 Trace 隔离 基于 Python contextvars.ContextVar 实现 ChatRequestContext，每次请求在协程独立上下文中运行。 彻底消除多并发协程共享全局变量造成的会话污染，Trace 记录按租户分表归档，严格保障数据隐私。
